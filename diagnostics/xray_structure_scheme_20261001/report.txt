WHY THE UI SAYS “NO STRUCTURES”
In app/xray_structures_ui.py, _build_structure_buttons reads the active scheme's structures and selects the first one, or None if the list is empty. _update_active_structure displays “No structures” when no active structure exists. The inspected active scheme has zero structures, so this matches the stored project state and is not a rendering bug.

The fish/specimen list can still display: refresh() obtains it independently from XRayProject.structure_specimens(), which returns human-confirmed specimen crops without requiring any scheme structures. The inspected project has 152 eligible specimens.

This scheme state is consistent with the code's new-project path: app/modules/xray_counts.py calls XRayProject.create(..., blank_scheme()), and app/xray_schema.py defines blank_scheme() with empty structures and traits. The bundled Phoxinus scheme exists separately; it is not automatically applied to this project's active scheme.

SELECTION PERSISTENCE
Crops stores selected_image_id and its PlateCropEditSession locally in XRayCropWorkspace. Structures stores selected_specimen_id locally in XRayStructureWorkspace and initializes it from that workspace's own specimen rows. XRayCountsRuntime creates separate Crops and Structures workspaces. No common current specimen is passed between Crops, Structures and Results or stored in ui_state. The saved crop batch is queue state, not a shared selected specimen.
