# MorphoLabel — предрелизный контрольный список (29.10.2026)

**Цель:** опубликовать рабочий Windows-релиз, а не продолжать научный перебор нейросетей.

Ветка: `fix/release-usability-20261029` → draft PR #6 → `feature/universal-multires-training-20261028` → PR #5 → `main`. Не менять базовую и активную модель в исходном проекте. Исходные ручные разметки остаются единственным научным ground truth.

## Что проверено

- GUI-мышь/фильтр локальности: 0,585 мс до первого перемещения в одном локальном тесте.
- Массовый Crop AI, 16 исходных плашек: 47,480 → 32,878 с (−30,8%); один ПК RTX 3060. На слабых ПК показатели неизвестны.
- 123 затрагиваемых теста прошли. Последний полный CI на исходном PR #6 до дополнительных изменений прошёл; новый CI нужен после всех коммитов.
- Исходная SQLite сохранена (контрольная сумма в `docs/RELEASE_USABILITY_VALIDATION_20261029_RU.md`).
- Обнаружено и исправлено: отдельный managed CUDA Python не мог импортировать обучающий worker из обычного PyInstaller PYZ, потому что `tools` не поставлялся как исходный файл. `packaging/morpholabel.spec` теперь включает `tools/train_universal_multires.py` и все необходимые исходные `app`/ `ai_runtime` модули. `.github/workflows/windows-release.yml` проверяет их фактическое присутствие в собранной программе. **Это ещё не подтверждение полного установленного GPU Train.**
- В `app/xray_multires_training.py` убрана задержка прогресса до завершения обучения. Добавлен тест реального дочернего процесса.

## NO-GO для публикации

1. Новый полный CI в PR #6 не зелёный.
2. Не собран Windows installer именно из итогового коммита ветки с изменениями.
3. Чистый установленный экземпляр не может запустить под отдельным managed CUDA Python скрипт обучения; предсказывает, но не позволяет переобучить Native Full + ROI Detail.
4. Не пройдено через GUI на **копии** проекта: Train → обе ветви → новый ZIP → импорт без автоактивации → перезапуск → прогноз → выбор/откат на старую модель; проверка SQLite/VERIFIED SHA до/после.
5. Не проверены offline/HTTP errors при проверке обновлений, Bio score с контролируемыми примерами и drag при фильтре локальности.
6. Результат установленной программы отличается от source code настолько, что Scientific export или схемы дают ошибку.

## План одного оставшегося Windows-прохода

- Дождаться зелёного CI; при красном исправить только реальную причину.
- Выполнить ручной `workflow_dispatch` на `fix/release-usability-20261029` для `windows-release.yml`, **без тега**. Сохранить artefact installer/хэши. Рабочий workflow на метках `v*` может автоматически публиковать prerelease, поэтому тег до принятия решения не создавать.
- Установить полученный EXE в чистую Windows-папку. Проверить bundled Python worker. По возможности проверить на втором Windows-ПК, но отсутствие второго оборудования указать в отчёте.
- На копии реального проекта проверить GUI training и inference, old models, данными source TIFF, SQLite и human verified; размеры, статус, отмену и progress.
- Отдельно определить, относится ли остановка `Testing 2/4 settings…` к Landmark training calibration; она не равна зависанию Native Full + ROI Detail. По журналу/таймеру убедиться, что benchmark действительно жив, или воспроизвести отказ; не устраивать многократные GPU-прогоны.
- Если всё PASS, пометить PR #6 ready, свести PR #6 в PR #5, а PR #5 в main, обновить changelog/версию **по принятому релизному плану**, только после этого создать release tag и GitHub Release. Пользователь должен лично одобрить публичную публикацию.

**Не утверждать**, что trained candidate точнее исходного: независимой prospective validation нет. Можно выпускать приложение с проверенной функцией обучения и явным human review, без неподтверждённых числовых обещаний.
