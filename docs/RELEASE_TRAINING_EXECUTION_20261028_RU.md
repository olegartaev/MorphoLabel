# MorphoLabel — единственный ближайший этап: довести Train до релизного качества

**Цель пользователя:** выпустить полноценную MorphoLabel. Рабочее распознавание Native Full + ROI Detail субъективно уже приемлемо при локальном использовании. Никаких новых архитектур, научных сравнений и ручных разметок сейчас не требуется. Порядок: (1) полностью отработать обучение → (2) пользователь даст короткий список остальных дефектов → (3) исправления, release QA, установщик, публикация.

## Исполнитель
**Codex Luna / reasoning Medium.** Одно большое законченное техническое задание, с несколькими связанными шагами и критериями остановки. High только при реальном архитектурном блокере. Использовать существующую локальную CUDA-среду и RTX 3060. Не устанавливать новые окружения и не искать повторно файлы, пути которых уже известны.

## Выполнение — один последовательный цикл
1. Продолжать существующую PR #5 в изолированном локальном worktree; `main` не трогать. Проверить actual parent metadata, порядок каналов научной схемы, source plate, исходные checkpoint (SHA256), режимы visibility, экспорт и импорт. Прогнать подготовленные CPU-тесты.
2. **Без подмены** выполнить один полный тренировочный цикл из существующих VERIFIED на **копии** проекта с текущими Native и Detail весами; использовать готовый `tools/train_universal_multires.py` (18 эпох/ветвь, если код/память позволяют), без подбора архитектур/порогов. Если есть технический баг, исправить его и добавить регрессионный тест. Не изменять SQLite/HUMAN VERIFIED, исходные изображения, исходный checkpoint. Модель-кандидат должна сохраняться отдельно и НЕ активироваться автоматически.
3. Проверить candidate ZIP, SHA256, scientific schema, ориентацию, чтение весов, реальные предсказания из кандидата на тех же экземплярах, что и у исходного гибрида. Парные исправленные/испорченные результаты: TV/AbdV/PredV/PreAp/ALL7 с доступными эталонами, но не заявлять это независимым тестом. Если качество явно деградирует, оставить рабочий гибрид, установить причину, не продвигать новый candidate. Выпуск приложения не требует недоказанных обещаний 70–80% ALL7.
4. Подключить **обычную кнопку Train** к корректному обучению: при выборе compatible multires parent обязательно запускать именно full+detail continued learning; при ImageNet / single-model parent сохранять legacy behavior. Не создавать ложную ситуацию, когда после Train новая модель имеет старую 768×256 архитектуру. GUI должен показывать режим и фактическую модель-родителя, VERIFIED число и source plates; давать прогресс двух фаз, безопасную ошибку, отмену по возможности, итог и возможность выбрать/активировать кандидат вручную. Не просить пользователя открывать терминал, передавать веса или знать Python.
5. Провести тест через настоящий интерфейс Windows на копии проекта: одна кнопка Train → корректная двухветвевая тренировка → отдельная модель → сохранение → перезапуск приложения → выбор модели → применение к существующим рентгенограммам → экспорт/import с тем же результатом → откат к исходному гибриду. Проверить сохранность старых ручных меток и моделей, и regressions legacy Train. Если невозможно провести всё через GUI, указать BLOCKED и точную причину; не утверждать, что готово.
6. В существующей feature-ветке сохранить код и тесты, написать один краткий русский отчёт: что работало, что исправлено, в каком режиме тестировано, GUI PASS/FAIL, CUDA PASS/FAIL, точность/paired regressions на доступном наборе, сохранность данных, оставшиеся блокеры. PR оставить draft до следующего этапа (список дефектов пользователя).

## Защита от бесполезной работы
Никаких GeCo2/CountEx/новых CNN, большого model search, переобучений «на всякий случай», задания пользователю новой ручной разметки, публикации тестовой версии. Не тратить время на косметику до работоспособного обучения. Не делать auto-promotion экспериментального candidate. Не утверждать обобщающую научную точность без независимых данных. После подтверждённого GUI обучения — STOP: пользователь сам перечислит оставшиеся дефекты, затем делаем один релизный проход.

**Определение готовности этого этапа:** обычный пользователь выбирает существующую многомасштабную модель и нажимает Train; MorphoLabel корректно продолжает обучение обоих компонентов на его VERIFIED-разметках, создаёт работоспособную отдельную модель и позволяет безопасно вернуться к прежней. Это проверено на Windows с настоящими файлами.
